diffdevil for GitHub · Extension Grammar v1

The reference for every place diffdevil appears inside a GitHub pull request. Companion to surface-grammar-v1 and identity-grammar-v1: those define the diffdevil language, this document defines how that language is spoken as a guest inside GitHub's own page. An implementer should not have to guess anything here; a future surface should find its rules here.

1

Contract

Replace GitHub where diffdevil knows something better. Preserve GitHub where it does not. Everything below follows from these four rules.

Inline belongs to GitHub.

diffdevil takes the seat GitHub already uses for the diffstat, in GitHub's typography, radii and colours. No extra rows, no injected toolbars, no sidebar, no sticky clones. Inside the pull request nothing is magenta.

why · the reader's eye already goes to that slot; a second object competes with the first and costs height on every tab.
Detail speaks diffdevil.

The popover has a GitHub shell (surface, border, elevation, position, dismissal) and diffdevil content grammar inside: one dominant value, evidence chips, decomposition beside raw, lanes, mono machine notation.

why · integration matters at the container; meaning matters inside. The same hierarchy appears in the CLI human report, the playground and the App.
Native survives until we have facts.

While loading, GitHub's counts stay untouched. On success they are replaced (default) or demoted to faint and desaturated (setting). On failure they are restored at full colour. The slot is never blank.

why · GitHub's raw churn is a valid fact; it is only a worse fact once Changed and its decomposition exist.
Our facts never yield to decoration.

Under width pressure the band rail drops first, then native raw, then the provenance word. Changed, its value, the decomposition triplet and the size label chip are never dropped; file paths truncate before file facts do.

why · the replacement-aware numbers are the reason the extension exists.

Aggregate seat

The diffstat slot in the PR header's tabs row, on every tab. One line, 20 px line-height, GitHub 12 px UI font, tabular numerals. Everything up to the rail is one button; the popover anchors to it.

replacement motion · loading → ready
Default · cross-fade in place, 160 msOur node is inserted before GitHub's diffstat in the same flex row with opacity: 0; its width is real from the first frame, so the row reflows exactly once. Then, on the next frame: GitHub's node fades opacity 1 → 0 over 100 ms and is set hidden at the end; our node fades opacity 0 → 1 over 160 ms starting at 40 ms. Easing cubic-bezier(.2,.7,.2,1), no translate, no scale, no colour animation. Total 200 ms; the row is never empty and never wider than its final width.
Setting "faint" · demote instead of removeSame insertion; GitHub's node does not fade out. It transitions color, opacity 1 → .7 and filter: saturate(1) → saturate(.3) over 160 ms with the same easing, in step with our fade-in. One motion, two nodes, no gap between them.
prefers-reduced-motion · single-frame swapInsert ours and hide (or demote) native in the same frame, no opacity ramp, no transition property. Identical end state. The same rule applies to every other seat transition: ready → moved, moved → ready, failure → ready after Retry.
Other transitionsready → moved: value to opacity .6 over 160 ms, chip and rail hidden in the same frame. → failure: our node hidden in one frame, marker inserted before native, native opacity → 1 and filter cleared over 160 ms. Popovers: §6. Per-file seats replace with the same cross-fade, staggered by nothing: all files swap together when the comparison resolves.

Why a cross-fade and not a plain swap: GitHub's own header updates (check counts, review state) fade in place, so a fade reads as the page updating itself rather than an extension arriving. Why never movement: the row is read peripherally; anything that slides or grows steals attention from the diff.

interaction contract · all three popovers
openClick or Enter/Space on the seat button. aria-haspopup="dialog", aria-expanded on the button; the popover is role="dialog", non-modal, labelled. Focus moves to the close button. positionBelow the seat, 8 px gap, right edge aligned to the seat's right edge; flips above when there is no room below; clamps 16 px from the viewport edges. Width 420 (aggregate) · 360 (toolbar, file); never wider than viewport − 32. scrollStays geometrically anchored to the seat while the seat is in view. When the seat leaves the viewport the popover closes. No sticky state, no re-anchoring to another element. close× button · Escape · click outside · clicking the seat again · the seat leaving the viewport · head change (moved state). Focus returns to the seat button. One popover at a time: opening another closes the current. hoverNothing opens on hover. Hover only shows host-native tooltips on the chip, rail segments, provenance word and marker glyphs. motionAppear: opacity 0 → 1 and 4 px rise over 160 ms, cubic-bezier(.2,.7,.2,1). Disappear: instant. Off under prefers-reduced-motion. narrowBelow 544 px the aggregate popover becomes a bottom sheet: full width, radius 12 top only, drag handle, same content, same dismissal. Copy factsWrites the canonical diffdevil human report for the popover's scope (whole comparison, or the focused file) — the exact text the CLI prints, produced by the shared presenter. Never a DOM scrape, never an extension-only format. Feedback "Copied ✓" 1.6 s on the link itself. Find in labels ↗Opens GitHub's own Labels picker in the PR sidebar and pre-fills its filter with the selected label name. The user applies (or creates) the label with GitHub's controls; diffdevil applies nothing. If the sidebar isn't on the current tab, navigate to Conversation first, then open. The button is present only while readback has not observed the label. Details ↗Opens the same comparison on the diffdevil web app in a new tab. Settings opens the extension's options page.

Themes and host tokens

Inline surfaces and popover shells use GitHub's Primer CSS variables, so they follow every host theme (dark, dark dimmed, high contrast, colour-blind, light) without a theme switch of their own. diffdevil tokens appear only inside the machine block. Hex values are the reference dark/light pair for fixtures and screenshots.

roletokendarklight
{{ t.role }}{{ t.token }}{{ t.dark }}{{ t.light }}
type

Inline and popover shell: host font stack, host sizes (12 px UI, 14 px value). Machine block and mono rows: IBM Plex Mono 400/500, shipped with the extension as woff2, fallback ui-monospace. Hero value and popover numbers: IBM Plex Sans 600/700, shipped likewise. Tabular numerals everywhere a number can change.

colour discipline

Diff green/red only as sign colour: host success/danger inline, --diff-add / --diff-del inside the machine block. Status colour only on a glyph and its word, never a background. Magenta only as the 3 px hero edge. Label colours come from the policy's label definition and are rendered as GitHub renders labels.

isolation

All injected nodes carry the data-diffdevil attribute and a dd- class prefix; the popover renders in a shadow root with the host variables inherited through :host. Nothing overrides a GitHub rule; GitHub's diffstat nodes are hidden with hidden (default) or given the faint class (setting), never removed, so failure can restore them in place.

Settings that change rendering

Two, both cosmetic, both applied identically to all three seats. Everything else (policy source, provenance, App connection) is a fact of the comparison, not a preference.

icon · glyph | colour | noneDefault glyph. Affects the icon in every seat. The popover header always uses the glyph. "none" removes the icon but never the word Changed.
nativeChurn · hidden | faintDefault hidden. "faint" keeps GitHub's counts and bar after ours in muted, desaturated form, in all three seats. Has no effect while loading or after failure: native is always at full strength there.

Not settings: showing or hiding the band rail (it is layout-driven), per-seat toggles, colour choices, alternative popover layouts. If a future preference is added, it must pass the same test: does it change what the reader learns, or only how it looks? Only the second kind belongs here.

Extension points

Where future capability plugs in without changing the grammar. Each one names the atom it extends.

Additional metricsAppear as further rows in the popover's policy "metrics" line and, if a policy makes one the focus, as the hero's measure chip. The inline seat shows only the focus metric.
Per-file rulesA file-level policy result earns one policy block in the file popover, in §6's style, and at most a compact evidence chip in the file seat. Never a chip that looks like the PR's size label.
Apply from the extensionWhen the extension can apply labels itself, "Find in labels ↗" becomes "Apply size/M" as a GitHub primary button; the readback lane then observes the result. The inline chip turns solid on observation, exactly as with the App.
Compare and commit pagesGitHub's compare view and single-commit view have the same diffstat seats. They reuse the aggregate and per-file seats with the comparison kind in the meta line ("two-dot", "commit").
Pull-request listsA list row may carry the changed unit and size chip in the row's metadata, nothing more. No rail, no popover from a list.
Other hostsA GitLab or Gitea adaptation keeps every atom and swaps the host token map (§9) and the seat selectors. The machine block and the diffdevil grammar inside the popover do not change.
