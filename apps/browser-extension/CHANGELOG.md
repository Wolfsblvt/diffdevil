# Source-candidate changes

## 1.0.0 browser source candidate

Added a portable, self-contained MIT browser API over the existing engine, with conservative acquisition, layered real policies, typed aggregate/file presentation and explicit optional App identity standing. Extracted the existing pure GitHub-file normalizer for reuse rather than forking measurements.

Added a Chrome Manifest V3 application with worker analysis, guarded public-source fallback, trusted-base policy acquisition, bounded rebuildable cache and recoverable settings transactions. Added GitHub lifecycle handling, full-PR and lazy per-file measurements, inspectable non-modal reports, dynamic bands, virtual label metadata and explicit native-picker handoff.

Added a complete options application with authored dark/light themes, search, Basic/Advanced discovery, literal stable anchors, icon choices, band/path/YAML and repository-policy editors, validation, per-setting reset, cache management, redacted diagnostics and portable import/export. Unsaved edits survive navigation within settings.

Added core, application, rendered-browser, acquisition and installed-browser qualification paths, candidate evidence receipts, Store listing/submission material and reproducible icon/screenshot/promotion assets. Nothing was merged, deployed or published by the local build.

Implemented the accepted Extension Grammar v1 in place of the earlier row-and-dump composition: three seats replace GitHub's diffstat in the header tabs row, the Files toolbar sentence and each file header, and the file tree's per-file counters receive the file treatment when GitHub shows them; the report is a GitHub shell around a diffdevil machine block with raw, files, policy and effect plan; loading, bounded, moved, policy-unavailable and failure states render as the grammar specifies; `Copy facts` copies the CLI's canonical human report. Rendering preferences are reduced to the icon and GitHub's raw churn (hidden or faint); the former per-seat, rail, pill, density and default-open settings are retired.

Repaired the first signed-in witness: rendered header paths are normalized of bidi marks before matching; a seat and the failure marker lead the complete native churn group instead of splitting its counts from its squares; private pull requests acquire through the `/changes` page's own embedded summaries and contents and, for the files GitHub did not embed, its same-origin `page_data/diff_entries` route, with bounded evidence only where GitHub declines a file, since the `.diff` route cannot be reached from a page context; and a same-comparison result is reattached from the worker cache across tab navigation with freshness confirmed in the background.

The canonical centre-seam `diffdevil/brand` glyph is integrated from its pinned accepted MIT source. Authenticated App report delivery remains a separate integration boundary; local results remain explicit. Installed/live/Windows evidence must be accepted separately.

Repaired the private signed-in journey: a private pull request's Conversation page and a soft navigation from it to Files changed now read the signed-in `/changes` page as their source instead of keeping a public-route failure, Retry reads again from the current route, an acquired result survives tabs that cannot name their comparison, and a read that is not instant shows a muted `reading` marker while GitHub's counts stay at full strength.

Added persistent continuity and first-use durability. The worker persists the engine's canonical report with its coverage, trusted policy evidence (templates included) and a last-confirmed-comparison pointer in a scoped, versioned IndexedDB cache; aggregate, file and report-text views are rebuilt from those facts under the current settings after a tab change, reload, worker suspension, browser restart or eviction instead of expiring, and an entry made under another engine, measurement semantics or report schema is a miss. A held comparison is shown at once, labelled cached, while a fresh read of the same route confirms it; when GitHub cannot be reached the exact result stays and is labelled not confirmed. Tabs and windows read a comparison once through a Web Lock.

Added a configurable automatic file limit (default 150). Files rendered near the viewport are measured first, then provider order; the rest stay bounded, GitHub-declined files are recorded as such and do not spend the limit, scrolling may measure further files in place within the same number, and **Analyze remaining files** and **Measure this file** are the explicit acts. The report always shows measured, bounded, provider-declined and total with the limit and what on-demand work added, and nothing is extrapolated. Measuring goes through a new engine function, `measureBoundedFiles`, so stepwise measurement reproduces the report of one complete acquisition.

Added a repository pause (local, from the report or Settings, with a way back on the page), scoped local-data controls (a per-repository and per-pull-request inventory with separate clears), and a single truthful first-install section in Settings at `#ready`. The aggregate packet no longer carries every file record.
