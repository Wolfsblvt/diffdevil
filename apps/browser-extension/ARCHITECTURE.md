# Browser-extension architecture

## Meaning

The browser is a new host for the existing measurement and policy system. DOM markup is placement and acquisition evidence, not a second analysis engine. The extension uses the presenter and application foundations already on its current `main` base without modifying the website or its public marketing surface.

## Boundaries and ownership

`src/diffdevil/browser/` is reusable MIT code. Its serialized acquisition and policy entry points validate data, invoke the existing parser/normalizer/compiler/evaluator and return the typed human projection. `github/changes.ts` is the original pure provider-file normalization extracted from `github/source.ts`; Node and browser consumers share it.

`apps/browser-extension/src/content/` owns github.com lifecycle and presentation. Its production controller accepts explicit platform dependencies for deterministic testing; the real bootstrap uses the actual location, acquisition and extension messaging. The content bundle imports the lightweight measurement formatter, not the compiler or parser. `src/background/` owns processing, settings transactions, bounded rebuildable storage and tightly scoped public API reads. `src/options/` is a separate full-tab application. Neither UI reconstructs numbers from CLI output or parses terminal styling.

The public `@wolfsblvt/diffdevil/browser` export is a closed ESM browser bundle. Fixed standalone validators are bundled ahead of time. No Node aliases, remote executable code, dynamic evaluation or schema compilation are required from consumers. Browser SHA-256 parity is tested against Node. Browser code cannot inspect proxies; the facade accepts serialized input, parses it into its own inert realm and uses the existing engine's validation boundary rather than trusting caller-owned executable objects.

## Comparison and acquisition

A comparison key contains host, normalized repository, PR number and full immutable base/head SHAs. A cache entry cannot become current merely because it was drawn at the same URL. Provider-generated JSON and narrowly selected immutable attributes can identify the comparison; arbitrary issue prose, abbreviated commit labels and GitHub line counters alone cannot.

The signed-in route starts from the page's own comparison. When the worker already holds a report for that exact comparison, the content script reattaches from it at once and confirms freshness against a fresh read of the same PR route in the background; a cached report exists only for a comparison that was confirmed for that PR before, so ordinary tab navigation never repeats acquisition, while a moved head keeps the old result visible as re-reading and reads the confirmed comparison. Otherwise the embedded comparison is confirmed against the same route before any policy or cache use. Source then comes from GitHub's `.diff` route when a page context can reach it (it redirects cross-origin without CORS, so it normally cannot; when it does answer, its text is whole and unbounded), else from the `/changes` page's own embedded file summaries (the complete inventory with raw counters) plus its same-origin `page_data/diff_entries` route (`paths`, `w=0`, `range=<head>`, with the `GitHub-Verified-Fetch`, JSON `Accept` and `X-Requested-With` headers the page sends), loaded in batches of eight, for the files the automatic limit selected, that GitHub did not embed. Embedded patches of files outside the selection are dropped so the measured count is exactly what the limit allows. An empty `isTooBig` result from a multi-path request is retried as a single-path request because the flag can describe the batch response budget; a failed single-path retry leaves only that file bounded, preserves successful batch-mates, and records the retry failure in a path-free acquisition diagnostic. That covers private pull requests without any token. Each entry is verified against the summary counters by the engine; a file GitHub declines as binary, submodule or truncated, or still too big when requested alone, is recorded as provider-declined, and a file the route does not return stays bounded (`PATCH_OMITTED`). The anonymous API is consulted only when the page offers no inventory or the signed-in route failed outright. Anonymous GitHub serves the classic page, so a public pull request is read from the API: its cost is one request per hundred files for the complete inventory whatever the limit, and the limit then bounds analysis and the packet, not requests. The public fallback reads PR metadata, paginated files, then metadata again without credentials. The latter uses at most thirty 100-file pages, honors transport/evidence limits and rejects a changed comparison. Explicit provider counters are cross-checked. A diff cut at a complete file boundary is still incomplete unless independent cardinality proves the file set. A malformed final hunk cannot bless exact facts; complete independent blocks remain useful when recoverable.

The signed-in diff and HTML response limit is 8 MiB. Serialized worker/acquisition requests are bounded at 24 MiB. Policies and individual templates are bounded at 256 KiB; at most sixteen explicit template paths are acquired. The API adapter has a 20 MiB aggregate pagination limit and a 20-second request timeout. These are execution limits, not statements that larger PRs have no changes. A source-limit failure is visible and never substituted with a fabricated empty report.

The content script's same-origin request is subject to the real browser's cookies, CORS, redirect and enterprise policies. The API host permission is not a claim that a content script can ignore those rules. The local Web sandbox cannot verify signed-in private GitHub access. Modern GitHub markup is an unstable provider interface; fixtures demonstrate the implemented selectors, not a promise about every future layout.

## Policy composition

Each participating policy is parsed and normalized through the real core. For higher layers, only explicitly declared normalized origins are overlaid. An implicit repository preset must not reset personal defaults. Named declarations and arrays replace; path members merge. Explicit presets replace inherited preset-origin values, not separately authored declarations. Every composed prefix compiles, so an upper override cannot hide a broken lower policy while valid upper expressions may reference lower declarations.

Composed: personal < repository at base < explicit personal override. Repository: repository, or personal if absent; personal overrides are ignored. Personal only: personal < explicit personal override, never repository. Empty include-only controls omit the member: an explicit `includeOnly: []` means include nothing in the core and is not a synonym for no restriction.

Guided UI values lower to ordinary policy declarations. Nonempty advanced YAML replaces that guided personal document. Names and optional colour metadata can decorate personally owned bands, but never overwrite a repository-authored band's provenance or facts. Partial label mappings are local handoff metadata, not an invented incomplete core label effect. A file projection evaluates its own core facts. Excluded files retain real measurements but have no virtual size classification.

Repository policy, including referenced templates, is read at the trusted base, not the pull-request proposal. A 404 is cached as absence only when exact-base access is independently confirmed. Invalid/unavailable policy leaves the report readable without a band. Users can deliberately choose Personal only rather than having the extension make that decision silently.

## Lifecycle and cache

Generation counters and AbortControllers prevent an old PR/head response from replacing the current view. Policy/settings changes use distinct context identities. Equivalent in-flight analysis is deduplicated; at most three different analyses are accepted concurrently, and work on one comparison is serialized so a second request finds what the first stored rather than analysing again. The worker keeps at most six contexts and 150 focused projections per context as an accelerator only: a missing context is rebuilt from persisted facts (below), never reported as an expired view. Source memory is transient. Twenty-four visible paths are requested per projection batch; failed/missing paths do not generate an endless retry loop.

A scoped repository-root MutationObserver watches provider changes. A cheap outer watcher only rebinds a detached root. There is no interval polling, broad rescanning for every page mutation, MutationObserver loop on injected nodes or global body opacity. Soft navigation, head changes, lazy files, root replacement, themes and explicit disabling are separate transitions. Per-file whole-PR facts are not injected into commit-only/narrowed views.

Rebuildable IndexedDB entries (schema 2) carry their scope (`github.com/owner/repository` and, for a report, the pull request), a compatibility string, an estimated serialized size and an access time. A 4–128 MiB LRU budget applies to every entry kind. Oversized entries are not persisted. The browser's independent quota may still reject a write; cache failure does not cancel a valid in-memory analysis. A generation boundary prevents a late operation repopulating data cleared by the user, in any tab, because one worker owns the cache. Clearing cache never clears user configuration. An older entry layout is dropped, not migrated: the cache is rebuildable.

## Persistence, coverage and continuity

The worker persists facts, not views. Three kinds of entry exist: the **report** (the engine's canonical normalized report plus its coverage), the **trusted policy evidence** for a repository at an exact base (present, absent or unavailable, the policy text, and every trusted template found or confirmed absent), and a **pointer** naming the last comparison confirmed for a pull request. Raw patches, page HTML, credentials and arbitrary provider bodies are never stored. The presentation (theme, icon, native-churn display, band names) and the effective policy projection are recomputed from the facts and the settings in force *now*; a presenter-only change never forces diff acquisition, a personal policy change reuses the cached report, and a changed trusted base invalidates only that repository policy entry.

A projection's identity is the comparison, the report's content identity and the effective policy digest. When the worker has lost its contexts (suspension, restart, eviction) a file, report-text or aggregate request names its comparison and the context is rebuilt from the stored report and policy evidence. If either is gone the request fails with `CONTEXT_EXPIRED` and the page reacquires. Entry compatibility is explicit: a report records the engine version, the measurement semantics and the report schema it was made under; an entry made under another meaning is a miss and is deleted when the worker starts using the cache. The keys carry no required parsing: scoped clears enumerate by the stored scope.

**Coverage** is persisted with the report: the automatic limit in force, how many files each kind of work measured (the first automatic pass, scrolling, an explicit act) and the files the provider declined, with why. A file is *measured* when the engine verified its patch against the provider's raw counters, *provider-declined* when GitHub supplied no lines (binary, submodule, too big, truncated, or no patch) or the file is not text, and otherwise *bounded*. The three always add up to the provider's file total, and the aggregate stays bounded, never extrapolated, until the files are measured. Measuring bounded files later goes through the engine (`measureBoundedFiles`): the persisted report's file records are replaced by the engine's own exact records, every aggregate is recomputed, and a patch that disagrees with the held raw counters leaves its file bounded. Measuring every file stepwise yields the same report identity as one acquisition with every patch.

**The automatic limit** (`analysis.maximumFiles`) bounds automatic whole-PR work, never navigation or inspection. It is one budget per comparison, shared by every automatic pass and by scrolling. When a comparison is first read, up to that many files are measured: the files rendered near the viewport first, then provider order. As files that are still bounded come on screen, whatever remains of that budget may be spent on them, in place, after the scroll settles: only files whose diff is in the viewport count, never files merely rendered further down; beyond that only an explicit act measures more: opening **Measure this file**, or **Analyze remaining files**, which runs in slices that are each persisted before the next. Raising the limit later lets one automatic pass spend the difference; lowering it never discards a fact. Declined files do not spend the limit. The limit is a lighter control inside the existing 24 MiB message, 20 MiB API and provider boundaries, which remain hard. The default (150) was chosen from the measurements in [Qualification](qualification.md): local cost is nearly independent of it, and the cost it governs is GitHub requests (eight files per request, three at a time on the signed-in route).

**Stale while revalidate.** A held comparison is shown at once with its provenance (`local · cached`) while a fresh read of the same route confirms base, head and file count. A trusted policy at an exact base is immutable, so confirming the comparison confirms its policy. `current` returns it to plain `local`; a moved head keeps the old result visible as re-reading and reads the new comparison; `unconfirmed` (GitHub unreachable, signed out, an unparseable route) keeps the exact result labelled `not confirmed` and checks again when the browser reports it is online or the reader navigates. A page that cannot name its comparison, such as a private Conversation tab, is offered the pointer's comparison and confirms it through the `/changes` route.

**Single flight.** One browser profile acquires a comparison once: tabs and windows hold a Web Lock named for the comparison while they read it, and the tab that waited then finds the stored report instead of reading GitHub again. Where a page has no usable lock manager the work simply runs. Inside the worker, identical requests share one analysis and different requests for one comparison are serialized.

**Pause.** A repository can be paused locally (keyed by host and normalized repository, stored in local extension storage, never synchronized). The worker rejects new analysis, cache lookups and provider reads for it; open tabs remove their seats and restore GitHub's counters, leaving one muted `diffdevil paused · Resume` line in the aggregate seat. Pause changes no stored data, `.diffdevil.yml`, App standing or GitHub state; clearing data is a separate scoped action.

**First install.** The service worker opens Settings at its `#ready` section only when Chrome reports the reason `install`. The section is a stable part of Settings, with no consent control and no required choice.

Small synchronized preferences and larger local policy/overrides use a serialized transaction with a durable previous-state journal. Interrupted writes recover before the next load/save. A failed rollback retains the journal and reports the failure; it does not silently delete policy. Reset is an explicit destructive operation. It also clears the settings page's local theme hint.

## Human and native surfaces

Seats replace GitHub's diffstat in place: the seat is inserted before the native node and the native node is hidden or demoted with a class, never removed, so a failure restores it exactly where it was. Inline surfaces use only host tokens; the report uses diffdevil tokens only inside its machine block and renders in a shadow root with the host variables inherited. The decomposition triplet is one indivisible unit, the rail is layout-driven, and the size chip's border style carries its standing. `Copy facts` asks the worker for the CLI's own human presenter over the same report; the content script never reconstructs text from the DOM. Monochrome/full-colour/none changes only the product mark, not measurement evidence. The monochrome default resolves the accepted shared centre-seam `diffdevil/brand` glyph copied unchanged from its pinned MIT source; this repository does not redraw its geometry.

The report is one non-modal anchored element. It does not lock page scrolling, request fullscreen or turn into a sidebar. It fits on the chosen side without covering its own trigger, has constrained inner scrolling, handles resize/zoom-sized viewports, closes on anchor disappearance and restores focus appropriately. All provider/path/policy text is inserted as text, not executable HTML.

The native label handoff opens and filters GitHub's visible picker. It never clicks the actual selection, sends a hidden mutation or creates a label. Native DOM readback can say a label was observed; it cannot prove the actor or response of a hidden provider operation. Other managed labels remain the user's native reconciliation decision.

## Optional App contract

`appStanding` compares the complete comparison, report, effective-policy, engine, schema, semantics and presenter identities. An older head is stale; a current report with different policy is not agreement; a version mismatch is incompatible. No guessed report-delivery endpoint exists. The current application always says local. A concrete authenticated producer/transport is a preserved external integration boundary, not permission to scrape a convincing-looking comment and display a checkmark.
