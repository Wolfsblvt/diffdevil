## Qualification mechanics

The ordinary test runner fails if no test files are discovered or if a discovered
file registers no actual test cases. It reports actual `node:test` summaries and
turns skipped files and tests into an ordinary failure. Focused tests can still be
run directly with `node --test`.

`npm run test:package` packs the built project, installs it outside the checkout,
executes the installed CLI and package exports, compiles the TypeScript API against
its declarations and runs the actual npm launcher command selected by the platform.
The Windows pass also invokes the installed PowerShell launcher directly through
`pwsh -File` before using npm's CMD dispatch. It tests the release-sensitive name,
author, version, licence, README, documentation, schema/preset assets and excludes
source tests, build tools, Action distribution, local artifacts and dependencies.

The Action distribution is native ESM rather than a bundled/minified file. The
builder copies the 12 locked runtime package trees with their package metadata,
licence files and notices; compiles source and standalone validators; writes one
runtime package, index wrappers and four `action.yml` files; then records every
source and output SHA-256 in `MANIFEST.json`. The builder's `--check` mode rebuilds
in temporary storage and refuses missing, extra or changed tracked bytes.

All ten Action consumer executions run the actual metadata-selected JavaScript
outside the repository with no consumer dependency installation: root analyze,
root plan, root apply, nested analyze, nested apply, sync verify, sync apply,
workspace-policy rejection, output-budget failure and an idempotent rerun. They
use an external fake GitHub HTTP server and real temporary output/summary files.
GitHub token masking remains an entry-point boundary; consumer tests record the
mask command before host evaluation.

## Windows qualification repair

The original Node 24 pass exposed Windows assumptions in the qualification tools,
not in product semantics. These repairs are part of the tested source:

- package installation goes through the npm CLI script selected by `npm_execpath`;
- executable lookup accepts Windows `.cmd` shims;
- installed launcher tests use `npm exec --offline --no -- diffdevil ...` for npm's
  own escaping and invoke the generated `.ps1` launcher directly with PowerShell;
- subprocesses and temporary-file deletion retry transient Windows filesystem
  locks instead of assuming POSIX timing;
- the output-protocol assertion normalizes `\r\n` emitted by Windows GitHub-style
  files while preserving value bytes; and
- the Windows path-separator test asserts the repaired basename rather than an
  accidentally POSIX-only string.

These changes make the consumer qualification portable; they do not claim native
macOS execution.

## Security and external effects

Current automated tests use fake GitHub HTTP and no real credential. Before a
write-capable canary or publication, independently inspect trusted policy
acquisition, stale head/base detection, provider permissions, owned-comment
reconciliation, output escaping, source/artifact trust and the install-free
runtime closure. Then run the authorized hosted canary against the exact reviewed
candidate, recording the actual actor, event type, effective permissions,
read/write revisions, selected policy, provider changes and readback.

The current design keeps apply policy on the PR base revision or an explicitly
pinned commit. Workspace policy is rejected for Action apply/definitions because
a checked-out path does not prove that content is trusted. `policy-repository` and
`policy-ref` require explicit pinned acquisition. PR contents, titles, branch names,
paths, body text and event metadata are data, never executable source. Apply
re-reads the target before every provider write, fails when the PR changes or
closes and reads back the managed labels/comments it owns.

A failed write can be ambiguous after the provider may have accepted it. The
observation journal retains attempted request, outcome and verification state;
the client never blindly repeats a write. Diagnostics and summaries redact the
known token, workflow-command payloads are escaped, multiline outputs use checked
random delimiters and output/summary budgets are enforced.
