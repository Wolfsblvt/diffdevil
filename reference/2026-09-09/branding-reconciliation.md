# Branding reconciliation: September 9, 2026

## Meaning

This dated note records the narrow correction from no default labels to a replaceable no-config size preset. The September 15 public edition removes conversational instructions while retaining the proposed text and rationale. The current canonical branding reference incorporates the selected correction; this remains historical evidence, not a competing brand source.

## Precedence

The selected product direction established that diffdevil ships sensible default size labels and a tiny workflow that applies/updates them without a config file, prior manual label setup, rules authored by the user, or automatic comments. That later instruction overrides earlier no-default-label positions in the founding transcript and branding guide.

It does not turn diffdevil into only a size labeler or a universal repository-governance taxonomy. It does not relax measurement honesty, managed-group boundaries, explicit application surfaces, or optional comments.

## Clauses to revise

### Product-category non-goal

The existing list says the product is not a default label taxonomy. Replace that narrow item with:

> a mandatory repository-wide label taxonomy.

Then add:

> diffdevil ships a replaceable default size-label preset for its no-configuration GitHub Action. That convenience does not impose a repository-wide labeling system or limit custom metrics, bands, rules, and labels.

### Band terminology

The existing band section emphasizes that the product does not impose a default naming religion and users define visible names. Replace its closing explanation with:

> The built-in size preset supplies neutral default band IDs and labels. Repositories may replace their thresholds, visible names, label definitions, or the entire preset. A preset is a useful starting policy, not a restriction on the language.

### Analysis versus application

Keep the principle that a token alone never implies mutation. Clarify the surface-specific entry behavior:

> `analyze` produces facts without provider mutation. `plan` records intended effects. `apply` performs effects explicitly. Selecting the root GitHub Action selects its documented default size-label application; `/analyze` is the read-only Action entry point. Comments remain off unless configured.

### Zero-configuration wording

The brand correctly rejects “zero-config magic.” Preserve that rejection, but update the preferred explanation to:

> Use the default size-label workflow without a configuration file, or customize the same policy engine with presets, shortcuts, scopes, formulas, and rules.

### Command vocabulary

Use `diffdevil labels verify` and `diffdevil labels apply` for the selected definition-check/reconciliation interface. The public sub-action path remains `sync-labels`. Earlier pre-release validate/sync CLI sketches do not create permanent aliases by themselves.

## Language name

Introduce detail in technical documentation as:

> detail is the optional expression language inside diffdevil.

Its machine identity remains `diffdevil-expr/1`. This is not a demon/ritual vocabulary system, an independent package brand, or required terminology for a user following the ordinary Action/CLI quickstart.

No changes to the hero, strapline, lowercase spelling, canonical npm/repository paths, restrained voice, or interpretation boundaries are proposed.

## Apply deliberately

These edits belong to the canonical branding file when integrated by its owner. Until then, this package marks the supersession explicitly and follows the latest owner decision. The historical source copy remains byte-identical so the change is attributable rather than silently backdated.
